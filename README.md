# DentFlow

Русскоязычная платформа администрирования стоматологий: публичный сайт, сайт клиники, запись, CRM, расписание, веб-чат, Telegram, автоматизации и кабинет владельца платформы.

**Статус выпуска:** функциональный MVP для закрытого Dev Stand и дальнейшего пилота. Операции записи и CRM выполняются сервером и сохраняются в PostgreSQL. Архив не является подтверждением юридического соответствия или готовности обслуживать реальные медицинские данные без дополнительной приёмки. Точные границы — в [ROADMAP](docs/ROADMAP.md) и [TESTING](docs/TESTING.md).

## Начните здесь

1. Установите [Docker Desktop](https://docs.docker.com/get-started/get-docker/) и запустите его.
2. Распакуйте проект в обычную папку.
3. Откройте терминал **в этой папке** — здесь должны быть `compose.yaml` и `README.md`.
4. Запустите один из вариантов:

**Windows PowerShell**

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

**macOS / Linux**

```bash
bash start.sh
```

Скрипт создаст локальные случайные секреты, соберёт контейнеры, применит миграции и добавит вымышленные данные. Во время первой сборки нужен интернет для скачивания зависимостей. Признак успеха — сообщение `DentFlow запущен`.

## Тестовые аккаунты

Действуют **только в созданном Dev Stand**. Production их не создаёт.

| Роль | Логин | Пароль |
|---|---|---|
| Владелец платформы | super@dentflow.local | Super-Demo-2026! |
| Владелец клиники | owner@dentflow.local | Owner-Demo-2026! |
| Управляющий | manager@dentflow.local | Manager-Demo-2026! |
| Администратор | admin@dentflow.local | Admin-Demo-2026! |
| Врач | doctor@dentflow.local | Doctor-Demo-2026! |
| Пациент | patient@dentflow.local | Patient-Demo-2026! |

Для полного теста справочников и настроек входите **как владелец клиники**. Администратор работает с записями, CRM, задачами и диалогами. Владелец платформы управляет клиниками, но не имеет автоматического доступа к их пациентам. Для проверки изоляции есть вторая клиника и `other@dentflow.local` / `Other-Demo-2026!`.

## Что работает

- Настоящая запись, подтверждение, перенос и отмена; защита от пересечения интервалов и повторного запроса.
- 2 филиала, 5 врачей, 12 услуг, 30 пациентов и 20 будущих записей Smile Avenue. Даты рассчитываются при seed относительно дня запуска.
- День, неделя, месяц и список в расписании; смены и перерывы, цены в копейках с отображением в рублях.
- CRM с 10 стадиями, карточки пациентов, задачи, диалоги, передача оператору, история и журнал действий.
- Общий движок веб-чата и Telegram: использует справочники и свободное время из базы; запись подтверждается отдельным действием пациента.
- Напоминания, задачи при пропущенном ответе, запрос обратной связи, согласия и маркетинговая реактивация. Лист ожидания в MVP представлен задачами сотруднику.
- Разделённые роли, сессии, проверка tenant, отдельные конфигурации и тома Dev Stand / Production.
- Super Admin: создание и блокировка клиник, владелец клиники, тарифы, лимиты и сводная статистика без просмотра медицинских данных.
- Управление согласиями, выгрузка собственных данных и обращение к оператору для удаления с проверкой сроков хранения.
- Защищённый сброс Smile Avenue, симулятор событий и ускоренная проверка напоминаний.

## Что требует подключения

| Компонент | Состояние в архиве |
|---|---|
| AI по умолчанию | Алгоритмический `demo`, без платной LLM. Выполняет реальные действия в тестовой БД. |
| Yandex AI Studio / GigaChat / локальная LLM | Серверные адаптеры и ограниченная классификация административных запросов. Нужны доступ, ключи, оценка условий обработки и живой тест. |
| Telegram | Код aiogram, общий движок, безопасная привязка, outbox и повторы. Нужен собственный BotFather token. |
| МИС | `MockMISAdapter` работает с внутренней БД; 1С, IDENT и Инфодент не подключены к чужим системам. |
| Платежи | Только DEMO. Списание денег, чеки и эквайринг отсутствуют. |
| Домены / HTTPS | Конфигурации и инструкция; подключаются на вашем сервере. |

На лендинге опубликован отдельный безопасный интерактивный пример: он не создаёт запись и не использует данные клиник. Заявка на подключение сохраняется в панели владельца платформы; email/SMS автоматически не отправляются.

## Команды на каждый день

```bash
docker compose ps
docker compose logs --tail=100 backend worker
docker compose stop
docker compose start
bash scripts/backup.sh devstand
```

Не используйте `docker compose down -v`, если хотите сохранить базу: `-v` удаляет Docker volumes. Для штатного сброса используйте кнопку внутри Dev Stand под Super Admin.

## GitHub

Загружайте **распакованное содержимое папки `dentflow`**, а не один ZIP. `.gitignore` исключает локальные секреты, зависимости и базы. Сам архив не содержит `.env`, API-ключей, истории пациентов, `node_modules` и виртуальных окружений. Для первого проекта удобно создать приватный репозиторий через GitHub Desktop. Подробности — в инструкции.

В `.github/workflows/ci.yml` есть проверки Python, PostgreSQL, TypeScript, сборки и Docker. Ручной CD находится в `deploy.yml`; он не активирует сервер без заданных вами секретов и ручного запуска. Лицензию для публикации собственного продукта выберите отдельно; условия сторонних библиотек сохраняются.
