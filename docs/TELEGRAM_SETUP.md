# Telegram: подключение собственного бота

Бот в архиве написан на aiogram и использует **тот же движок диалога и ту же БД**, что веб-чат. Без вашего токена и явного включения Telegram никакие сообщения не отправляются. Проверка кода с синтетическими ответами API не заменяет живую проверку своего бота.

## 1. Создайте отдельного тестового бота

1. Откройте в Telegram официальный [BotFather](https://t.me/BotFather). Проверьте username: `@BotFather`.
2. Отправьте `/newbot`.
3. Задайте понятное имя, например «DentFlow тест».
4. Укажите свободный username, оканчивающийся на `bot`.
5. BotFather выдаст token. Сохраните его как секрет; не вставляйте в исходники и не публикуйте скриншот с ним.

Dev Stand и production должны использовать **разных ботов и разные токены**. Если токен стал публичным, перевыпустите его через BotFather и обновите окружение.

Официальные справки: [первые шаги Bot API](https://core.telegram.org/bots/tutorial), [Telegram Bot API](https://core.telegram.org/bots/api), [aiogram](https://docs.aiogram.dev/en/latest/).

## 2. Запишите настройки

В локальном `.env` измените:

```dotenv
TELEGRAM_ENABLED=true
TELEGRAM_BOT_TOKEN=ВАШ_СЕКРЕТНЫЙ_ТОКЕН
TELEGRAM_BOT_USERNAME=your_test_bot
TELEGRAM_CLINIC_SLUG=smile-avenue
```

Username вводится без `@`. Slug — часть адреса после `/clinic/`, не название клиники с пробелами. В .env.production используйте slug созданной production-клиники и её отдельный токен.

Пример `.env.example` не редактируйте под секреты: он хранится в GitHub. Секреты принадлежат только игнорируемым `.env` и `.env.production`. Значения доступны backend/worker, но не включаются в клиентский JavaScript.

## 3. Запустите дополнительный сервис

Из папки проекта:

```bash
docker compose --profile telegram up -d --build --wait --wait-timeout 300
docker compose logs --tail=80 telegram worker
```

Это пересоздаст сервисы с обновлёнными env и добавит процесс бота. Для production:

```bash
docker compose --env-file .env.production -f compose.production.yaml --profile telegram up -d --build --wait --wait-timeout 300
```

Используется **polling**: бот сам запрашивает новые события у Telegram. Публичный HTTPS webhook для этого процесса не нужен. Не запускайте два polling-процесса с одним token. Если ранее у бота настроен webhook, код останавливается с объяснением, не удаляя чужую конфигурацию автоматически. Сначала проверьте назначение существующего бота, затем осознанно отключите его webhook по официальному Bot API или создайте отдельного тестового бота.

Один token / процесс связан с одной клиникой. Для нескольких ботов создайте отдельные сервисы с собственными token, TELEGRAM_CLINIC_SLUG и изолированными секретами. Система не предлагает пользователю выбрать tenant произвольным сообщением.

## 4. Проверьте команды

Откройте **личный** чат со своим ботом и нажмите Start:

| Команда | Результат |
|---|---|
| /start | Приветствие и меню |
| /book | Выбор услуги, филиала, врача и свободного времени |
| /appointments | Записи, привязанные к этой подтверждённой сессии Telegram |
| /help | Доступные действия |
| /human | Задача сотруднику и передача диалога |

Запись создаётся только после выбора времени, ввода имени/телефона и отдельного подтверждения согласия. Тестируйте вымышленными данными. Затем откройте кабинет клиники и проверьте календарь, CRM и историю разговора. Посмотрите, что source визита равен telegram.

Групповые чаты не поддерживаются: в них бот не обрабатывает пациентские сообщения. Фото, медицинские документы, аудио и голосовые сообщения не загружаются и не анализируются. Для обращения используйте текст и меню.

## 5. Свяжите сайт и Telegram безопасно

Одинаковый телефон не объединяет профили. Чтобы Telegram увидел запись, созданную на сайте:

1. На сайте клиники создайте запись в своём браузере либо войдите под привязанным аккаунтом пациента.
2. Откройте «Мои записи» → «Связать Telegram».
3. Приложение выдаст случайную одноразовую ссылку либо команду `/start link_...`.
4. Откройте ссылку в **своём** Telegram или отправьте команду своему боту.
5. Получите сообщение об успешной привязке и выполните `/appointments`.

Ссылка действует 10 минут, используется один раз и теряет силу после завершения исходной веб-сессии. Не отправляйте её другому человеку: она подтверждает доступ к вашим записям. Перепривязка уже связанного Telegram к другому пациенту запрещена; автоматическое слияние профилей не выполняется.

Если TELEGRAM_BOT_USERNAME не указан, система возвращает команду для ручной вставки. Если бот ещё не запущен, выдача кода сама по себе его не включает.

## 6. Передача сотруднику

Отправьте `/human`. В кабинете появится задача. Сотрудник открывает Диалоги, перехватывает разговор и отправляет организационный ответ. Для Telegram ответ попадает в outbox и отправляется worker в тот же проверенный приватный чат. Сообщение нельзя направить произвольному контакту из поля телефона.

Разрешены административные вопросы: время, адрес, организационные условия. Не отправляйте медицинские карты, диагнозы, результаты обследований, назначения и снимки. Код блокирует часть очевидных медицинских формулировок в ответах сотрудника, но такой фильтр не заменяет правила работы персонала и правовую оценку канала.

## 7. Напоминания и состояния доставки

Пациент отдельно включает напоминания. Автоматические тексты содержат минимум организационной информации. Реактивация дополнительно требует маркетингового согласия. Отзыв согласия отменяет ожидающие сообщения, а worker повторно проверяет условия перед отправкой.

| Состояние | Значение |
|---|---|
| pending | Сообщение в очереди |
| sending | Взято worker на отправку |
| delivered | Telegram API принял сообщение; прочтение пациентом не подтверждается |
| failed | Терминальная ошибка либо исчерпаны попытки |
| suppressed / cancelled | Доставка отменена условиями доступа или согласиями |

Ошибки и недоступность Telegram не отменяют уже сохранённую запись. После временного сбоя очередь повторяет отправку с ограничением числа попыток. При аварии между отправкой и фиксацией результата возможен повтор сообщения (*at least once*). Идемпотентность записи пациента от этого не зависит.

Если Telegram недоступен, сайт и внутренние уведомления продолжают работать. SMS, email и телефония в этой версии не подключены; нельзя обещать их как автоматический запасной канал.

## 8. Частые проблемы

**Бот молчит.** Проверьте token, TELEGRAM_ENABLED, правильный slug, состояние контейнера и `docker compose logs telegram`. После изменения .env нужен `up -d`, одного редактирования файла недостаточно.

**Конфликт polling.** Тот же token запущен ещё где-то. Остановите вторую копию, не смешивайте dev и production.

**Кнопка устарела.** Диалог уже изменился. Повторите `/book` или `/appointments`. Это защита от применения старого выбора к новой записи.

**Мои записи пусты.** Созданный на сайте визит не связывается по телефону; выполните одноразовую привязку. Запись в другом tenant остаётся недоступной.

**Диалог виден, но уведомление не пришло.** Проверьте согласие, работу worker, статус pending/failed и то, что пациент не заблокировал бота. Внутреннее delivered не равно Telegram delivered: смотрите поле канала.

**Не удаётся получить токен/API из вашей инфраструктуры.** Проверьте сетевую доступность и применимые условия использования. Не отключайте TLS-проверку и не направляйте медицинские данные через случайный сторонний proxy.

До коммерческого использования проверьте LEGAL_COMPLIANCE.md. Подключение Telegram — отдельное эксплуатационное и правовое решение, а не следствие наличия кнопки в интерфейсе.
