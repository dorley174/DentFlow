# Dev Stand: подробный сценарий проверки

## Доступ и роли

Локальный адрес: **http://localhost:8080**. На отдельном сервере используйте SSH-туннель из DEPLOYMENT.md; публичный dev-домен в архиве не создан.

| Роль | Логин | Тестовый пароль | Что проверять |
|---|---|---|---|
| Super Admin | super@dentflow.local | Super-Demo-2026! | Создание/блокировка клиник, тарифы, сводка, сброс |
| Clinic Owner | owner@dentflow.local | Owner-Demo-2026! | Все операции своей клиники, сотрудники, справочники |
| Clinic Manager | manager@dentflow.local | Manager-Demo-2026! | Записи, настройки, справочники; без управления сотрудниками |
| Administrator | admin@dentflow.local | Admin-Demo-2026! | Записи, CRM, задачи, диалоги |
| Doctor | doctor@dentflow.local | Doctor-Demo-2026! | Собственное расписание и связанные пациенты |
| Patient | patient@dentflow.local | Patient-Demo-2026! | Свои записи и согласия |
| Другая клиника | other@dentflow.local | Other-Demo-2026! | Изоляция второй клиники Аврора Дент |

Панель переходов Dev Stand показывает ссылки на роли и страницы, но не выдаёт права. Для смены роли нужно выйти и войти другим аккаунтом. Super Admin не может читать клинические данные через `/admin`. Пациент не может превратить себя в сотрудника.

Для тестирования двух сторон используйте два браузера либо обычное окно для сотрудника и инкогнито для пациента. Несколько вкладок одного браузерного профиля разделяют cookie: вход в одной вкладке меняет роль в других. После logout исходные возможности гостевой сессии отзываются; это сделано намеренно.

## Исходные данные

Smile Avenue содержит 2 филиала, 5 врачей, 12 услуг с ценами в рублях, недельные смены, 30 вымышленных пациентов, 20 будущих записей, CRM, 4 примера диалогов и задачи. Визиты распределены на ближайшие дни после seed; для просмотра переключите календарь на завтра или неделю.

Номера `+7000…` и адреса демо-города синтетические. Второй tenant Аврора Дент нужен для проверки разграничения. Сам факт имени в демонстрации не утверждает существование реального врача или клиники.

## Тест 1. Запись через сайт

1. Пациент открывает `/clinic/smile-avenue`.
2. Изучает врачей и цены; запускает форму записи.
3. Выбирает услугу, филиал, врача, будущую дату и свободный интервал.
4. Вводит вымышленные имя и телефон. Согласие на запись обязательно; напоминания и маркетинг не подменяют его.
5. Нажимает подтверждение. Успех показывается только после ответа backend.
6. Открывает «Мои записи» и видит созданный визит.
7. Сотрудник открывает Расписание / Записи, выбирает ту же дату и обновляет данные.
8. В Пациентах и CRM появляется тот же человек и лид. Лид не должен возникать заново при сетевом повторе того же запроса.

Отказ от обязательного согласия не создаёт запись. Доступные интервалы рассчитываются сервером; если другой пользователь занял время между просмотром и подтверждением, возвращается конфликт и предлагается выбрать заново.

## Тест 2. Запись через настоящий чат

На сайте Smile Avenue откройте чат. Используйте «Записаться на приём», затем варианты услуги, филиала, врача и времени. При запросе контактов отправьте, например:

```text
Тестовый Гость, +70000000222
```

Затем выберите отдельную кнопку подтверждения записи с нужным вариантом напоминаний. Проверьте тот же визит в административном календаре. В Диалогах видна история, в CRM — карточка. Это общая БД и один сервис записи, а не независимая демонстрация.

Вопрос о ценах показывает актуальный справочник. Медицинский вопрос передаётся человеку; AI не ставит диагноз и не назначает лекарства. Публичный демо-чат на главной DentFlow не заменяет этот тест.

## Тест 3. Перенос и освобождение времени

В кабинете сотрудника откройте созданный визит и перенесите его на доступное время. Обновите «Мои записи» пациента: новое время должно совпасть. Исходный интервал снова должен появиться в доступных. Второй пациент в новом инкогнито-профиле может его занять.

Попытка занять пересекающийся интервал должна завершиться 409. Проверяется полная длительность, а не только совпадение начала. Перерыв и часы вне смены не предлагаются. После отмены запись сохраняется в истории со статусом, время освобождается.

## Тест 4. Человек перехватывает диалог

Пациент нажимает «Позвать администратора». В кабинете появляется задача. Сотрудник открывает Диалоги, выбирает обращение, включает режим сотрудника и отвечает. Ответ сохраняется; пациент видит его после обновления чата. Пока работает человек, AI не продолжает самостоятельную запись в этом диалоге. При необходимости сотрудник явно возвращает режим AI.

Telegram использует тот же механизм. Для его проверки сначала подключите собственный бот по TELEGRAM_SETUP.md; без token никакие сообщения реальным людям не отправляются. Ответы оператора в Telegram ограничиваются административным общением.

## Тест 5. CRM, задачи и справочники

Управляйте стадией лида перетаскиванием или выбором стадии. Изменение сохраняется через API. Создайте задачу, назначьте ответственного и завершите её. Под Owner добавьте филиал, услугу и врача. Свяжите врача с услугой и добавьте смену на нужный день. Только после этого на сайте появляются свободные интервалы.

Если смена конфликтует с уже созданными будущими визитами, backend не должен молча скрывать их: сначала перенесите/отмените визиты. Сотрудник другой клиники не может назначаться ответственным.

## Тест 6. Автоматизации и ускоренное время

Откройте Автоматизации под Owner или Manager. Включайте/отключайте правила и задавайте задержки. Кнопка запуска оценивает реальные условия и сохраняет уведомления/задачи. Фоновый worker делает это автоматически, пока контейнер работает.

В Dev Stand симулятор поддерживает:

| Событие | Результат |
|---|---|
| Новое обращение | Синтетический пациент и новый лид |
| Отмена / свободный слот | Отменяет подходящий будущий тестовый визит |
| Пропущенный ответ | Диалог с выдержанной задержкой и задача сотруднику |
| Задача | Новая тестовая задача |
| Напоминание | Оценка времени перед ближайшим визитом без ожидания реальных суток |
| Передача человеку | Диалог в human и задача |

Ускорение — параметр оценки правил; системные часы сервера не меняются. В production такое ускорение запрещено. Дедупликация не позволяет одному правилу повторно создать то же уведомление для того же визита/времени.

Различайте внутреннее уведомление, очередь Telegram и действительно принятую Telegram API отправку. Отзыв согласия на уведомления отменяет ожидающие уведомления; отзыв маркетинга отдельно отменяет реактивацию. Worker повторно проверяет разрешение перед отправкой.

## Тест 7. Изоляция и права

Выйдите из Smile Avenue и войдите как other@dentflow.local. В кабинете должна появиться Аврора Дент, без пациентов и визитов Smile Avenue. Под Doctor должны отображаться собственные приёмы, а не общая CRM. Под Patient `/admin` и `/super` должны быть запрещены. Super Admin видит сводку и управление подписками, без выдачи полного списка чужих пациентов.

Знание чужого UUID не даёт права на объект. Нельзя объединять людей по совпадающему телефону: другой браузер без доказанного владения получает отдельную личность.

## Сброс

Войдите как Super Admin. Нажмите «Сбросить тестовые данные», прочитайте подтверждение и введите требуемую фразу `RESET SMILE AVENUE`. Восстанавливается только Smile Avenue; другая клиника остаётся. Тестовые сотрудники и пациенты Smile Avenue должны войти заново.

Сброс невозможен в production: есть проверка окружения, флага, имени БД, роли и признака демо-клиники. Для обычной остановки используйте `docker compose stop`, а не сброс.

## Как закончить приёмку

Сохраните дату, commit, окружение и результат каждого сценария. Не подменяйте живой тест Telegram проверкой кода без токена. Технический отчёт о выполненных в среде разработки проверках находится в TESTING.md; после развёртывания повторите сценарии в настоящем браузере на вашей VM.
