# Настройка административного помощника и AI-провайдеров

Дата проверки документации провайдеров: **05.11.2026**. Внешние адаптеры подготовлены по официальным спецификациям. Проверка с настоящими API-ключами, списание средств и оценка качества конкретных моделей в этой поставке **не выполнялись**.

## 1. Что работает сразу

По умолчанию DentFlow использует `demo` — автономный алгоритмический административный помощник. Он берет услуги, цены, врачей и свободные интервалы из БД приложения; проводит запись, перенос, отмену и передачу сотруднику через backend. Для этого не требуется нейросеть или платежный аккаунт AI-провайдера. Это рабочая логика приложения, а не готовый свободно разговаривающий LLM-консультант.

Разделение ответственности:

| Компонент | Его задача |
| --- | --- |
| `backend/app/services/chat.py` | Состояние диалога, административные сценарии, проверка контекста и вызов бизнес-операций |
| `backend/app/adapters/ai.py` | Общий интерфейс `AIProvider`, выбор провайдера, HTTP-запрос и чтение ответа |
| `safe_intent()` | При разрешенных условиях — классификация короткого безопасного административного запроса |
| Службы расписания и MockMISAdapter | Реальные цены, доступность времени и изменение записей в БД DentFlow |
| Администратор клиники | Обработка передачи человеку, нестандартных ситуаций и вопросов вне автоматического сценария |

Модель не получает полномочия напрямую менять записи, выбирать произвольный tenant или выполнять команды из сообщения. Ее ответ не является источником цены или свободного времени. Медицинские рекомендации, диагнозы и назначения не относятся к назначению помощника.

## 2. Границы внешнего классификатора

Внешний вызов возможен только после явного включения и выбора провайдера. Дополнительно `safe_intent()` проверяет сообщение:

- Не более 240 символов.
- Нет цифр и символов `@`, `+`, `:`, `/`.
- Каждое извлеченное слово входит в закрытый словарь административных формулировок.
- Провайдер получает только нормализованные слова этого запроса и фиксированную инструкцию классификации.
- Ответ принимается только из набора `services`, `doctors`, `hours`, `book`, `human`, `greeting`, `unknown`.

История пациента, имя, телефон, идентификаторы записи, медицинский текст, сведения из карточки, цены и слоты в этот запрос не добавляются. Если сообщение не прошло фильтр, провайдер не вызывается: продолжает работать локальный сценарий. Если API недоступен или вернул другой ответ, помощник также использует базовую логику.

Это намеренно узкий способ применения LLM. Он не делает внешнюю модель универсальным консультантом и не гарантирует, что любой будущий вызов `complete()` будет безопасен. При доработке проверяйте все вызывающие места: сам низкоуровневый `complete(system, prompt)` принимает переданный разработчиком текст. Не передавайте ему диалог или медицинскую карту без отдельного проектирования и правовой оценки.

## 3. Общие переключатели

Начальные настройки в `.env`:

```dotenv
AI_PROVIDER=demo
AI_EXTERNAL_ENABLED=false
```

`AI_EXTERNAL_ENABLED` — глобальный запрет/разрешение сетевых вызовов LLM. Он действует и на `local`, поскольку локальный inference-сервер также вызывается по сети. Значение `false` оставляет алгоритмический режим доступным.

`AI_PROVIDER` выбирает провайдера по умолчанию для фабрики адаптеров и команды проверки соединения. В рабочем чате дополнительно используется сохраненная настройка провайдера конкретной клиники в разделе AI. Изменение `.env` само по себе не переписывает эту запись в БД. Для пилота настройте окружение и выберите тот же провайдер в настройках нужной клиники.

Секреты храните только на сервере в `.env` или менеджере секретов. Не помещайте их в переменные `NEXT_PUBLIC_*`, GitHub, браузерный код, скриншоты, экспорт настроек или чат пациента. Секреты в примерах ниже — поля для ваших значений.

## 4. Yandex AI Studio / YandexGPT

```dotenv
AI_PROVIDER=yandex
AI_EXTERNAL_ENABLED=true
YANDEX_API_KEY=CHANGE_ME_SERVICE_ACCOUNT_API_KEY
YANDEX_FOLDER_ID=CHANGE_ME_FOLDER_ID
YANDEX_MODEL=yandexgpt-5.1
```

Подготовленный адаптер использует обычный сервисный API с авторизацией `Authorization: Api-Key …`. API-ключ должен относиться к сервисному аккаунту с требуемыми правами на выбранный каталог и действующим платежным аккаунтом. Это не настройка персональной подписки AI Studio: у нее иной способ доступа. Актуальный порядок выдачи ключей и прав приведен в [официальной документации авторизации](https://aistudio.yandex.ru/ru/docs/ai-studio/api-ref/authentication).

Технический контракт адаптера:

```text
POST https://ai.api.cloud.yandex.net/foundationModels/v1/completion
Authorization: Api-Key <secret>
x-data-logging-enabled: false

modelUri: gpt://<folder_id>/yandexgpt-5.1
messages: [{role: system, text: ...}, {role: user, text: ...}]
completionOptions: {stream: false, temperature: 0, maxTokens: "256"}
```

Ответ читается из `alternatives[0].message.text`; счетчики — из `usage`. Адаптер также учитывает обертку `result`, встречающуюся в формате ответа. См. [метод completion](https://aistudio.yandex.ru/ru/docs/ai-studio/text-generation/api-ref/TextGeneration/completion).

Модель по умолчанию — `yandexgpt-5.1`. По [списку моделей](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models) на дату исследования для YandexGPT Lite указано прекращение доступности 15.11.2026, поэтому переносить старое значение `yandexgpt-lite` в новую установку не следует. Перед запуском проверьте доступность точного идентификатора в своем аккаунте. Модель с поддержкой только OpenAI-compatible API не обязательно работает с используемым здесь native `completion`.

Заголовок `x-data-logging-enabled: false` реализует документированный способ исключения содержимого запросов из использования для улучшения сервиса. Он не является обещанием отсутствия любых технических журналов или юридическим разрешением на передачу персональных данных. Прочитайте [отключение логирования](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging) и [хранение данных](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/data-storage).

В [документации квот](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/limits) базовое число одновременно выполняемых синхронных запросов без подписки — 10. Фактическую квоту, стоимость и доступные модели проверяют в аккаунте; код не увеличивает лимиты автоматически.

## 5. GigaChat

```dotenv
AI_PROVIDER=gigachat
AI_EXTERNAL_ENABLED=true
GIGACHAT_AUTH_KEY=CHANGE_ME_AUTHORIZATION_KEY
GIGACHAT_SCOPE=GIGACHAT_API_B2B
GIGACHAT_BASE_URL=https://api.giga.chat/v1
GIGACHAT_MODEL=GigaChat
GIGACHAT_CA_BUNDLE=
```

**Условия подключения изменились:** официальная страница для юридических лиц указывает, что с 01.09.2026 новые платные клиенты подключаются через Cloud.ru. Приведенный OAuth-адаптер предназначен для аккаунтов, которым доступен описанный GigaChat API. Нельзя считать его автоматически совместимым с договором, ключом и endpoint нового продукта Cloud.ru. Для такого аккаунта сначала сверить официальную спецификацию и при необходимости сделать отдельный адаптер. Источники: [подключение юридических лиц](https://developers.sber.ru/docs/ru/gigachat/quickstart/legal-tokens-purchase), [тарифы и переход](https://developers.sber.ru/docs/ru/gigachat/tariffs/legal-tariffs).

Авторизация подготовленного адаптера:

```text
POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth
Authorization: Basic <authorization_key>
RqUID: <UUID v4>
Content-Type: application/x-www-form-urlencoded

scope=GIGACHAT_API_B2B
```

Значение `GIGACHAT_AUTH_KEY` — ключ авторизации, полученный для конкретного аккаунта, а не самостоятельно придуманная строка. После получения токена запросы идут с `Authorization: Bearer …` на `https://api.giga.chat/v1/chat/completions`. По документации токен действует 30 минут; адаптер обновляет его с запасом до истечения. Новый базовый домен опубликован в [справочнике API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api); формат сообщения — в [методе chat/completions](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-chat).

Согласуйте scope со своим доступом:

| Scope | Назначение в документации |
| --- | --- |
| `GIGACHAT_API_PERS` | Доступ физического лица |
| `GIGACHAT_API_B2B` | Доступ бизнеса с пакетами |
| `GIGACHAT_API_CORP` | Корпоративная оплата по использованию |

Наличие персонального доступа не подтверждает право и условия коммерческой эксплуатации. Доступные модели получите по официальному API своего аккаунта; значение `GigaChat` в конфигурации не обещает, что именно эта модель включена в любой договор.

Проверка TLS включена. Если аккаунту требуется доверенный корневой сертификат, получите его из официального источника, примонтируйте файл в контейнер и укажите путь **внутри контейнера** в `GIGACHAT_CA_BUNDLE`. Не отключайте проверку сертификата и не используйте `verify=False` как способ исправить соединение.

По [странице ограничений](https://developers.sber.ru/docs/ru/gigachat/limitations) стандартный параллелизм составляет 1 запрос для физлиц и 10 для юридических лиц; договор или сервис подключения может задавать другие значения. При `429` нужен контроль нагрузки, а не бесконечное повторение запроса.

## 6. Локальная модель

Локальный адаптер ожидает сервер с поддержкой OpenAI-compatible `chat/completions`. Например, Ollama документирует [поддерживаемую часть такого API](https://docs.ollama.com/api/openai-compatibility).

```dotenv
AI_PROVIDER=local
AI_EXTERNAL_ENABLED=true
LOCAL_LLM_URL=http://host.docker.internal:11434/v1
LOCAL_LLM_MODEL=CHANGE_ME_INSTALLED_MODEL_ID
LOCAL_LLM_API_KEY=
```

`LOCAL_LLM_MODEL` должен совпадать с фактически установленной моделью. Модель и inference-сервер не загружаются этим проектом автоматически. Проверьте лицензию конкретной модели, память, скорость и качество русского языка на своем наборе задач. Поддержка части OpenAI API не означает полной совместимости всех функций.

В контейнере `localhost` указывает на сам контейнер. Для Linux доступ к серверу на хосте через `host.docker.internal` может потребовать явного `extra_hosts: ["host.docker.internal:host-gateway"]`; другой вариант — внутренний DNS-адрес сервиса в общей Docker-сети. Не добавляйте в URL второй `/chat/completions`: адаптер сам дописывает этот путь к `/v1`.

Адрес — настройка доверенного оператора, а не поле пациента. Не открывайте inference-порт в интернет без отдельной защиты. Для production сервер модели также должен находиться в согласованной инфраструктуре России; название режима `local` не доказывает географию, отсутствие телеметрии или соответствие закону. При использовании облачных моделей внутри локального runtime проверьте фактический сетевой маршрут.

## 7. Проверка соединения без данных пациентов

После изменения `.env` пересоздайте использующие его контейнеры; простой `restart` не гарантирует применение нового окружения. Для базового стенда:

```bash
docker compose up -d --force-recreate backend worker
docker compose exec backend python -m app.adapters.ai
```

Если запущен отдельный Telegram-контейнер, примените новое окружение и к нему по инструкции канала. Команда проверки отправляет фиксированную техническую фразу без данных пациентов и возвращает JSON со статусом. Успех означает, что выбранный API ответил на этот запрос; он не подтверждает качество, юридическую допустимость, приемку всего чата или правильность финансового учета.

Порядок пробного включения:

1. Использовать отдельный тестовый аккаунт/проект, лимит бюджета и синтетические данные.
2. Проверить соединение командой выше.
3. Выбрать провайдера в AI-настройках тестовой клиники.
4. Проверить запрос вроде «какие услуги»: отображаемые услуги должны совпасть с БД.
5. На уровне тестов/контролируемого перехвата HTTP проверить, что имя, телефон и произвольный медицинский текст не вызывают классификатор. Не печатать реальные данные в журнал для такой проверки.
6. Воспроизвести отсутствие ключа, отказ API, таймаут и некорректный ответ: базовый помощник должен остаться доступен.
7. Проверить подтверждение записи, конфликт времени и передачу администратору через общий backend.

Не используйте реальные истории болезни как тестовый корпус. Правовая и организационная подготовка описана в [LEGAL_COMPLIANCE.md](LEGAL_COMPLIANCE.md).

## 8. Учет токенов, ошибок и денег

Адаптеры читают счетчики токенов, если провайдер их возвращает. В текущем приложении `AIUsage.cost_kopecks` равен `0` для алгоритмического режима и `null` для внешнего вызова, стоимость которого еще не рассчитана. Это техническая заготовка учета, а **не расчет реального счета провайдера**. Отсутствие суммы в интерфейсе не означает бесплатные внешние вызовы. Фактическое начисление проверяйте в кабинете поставщика.

До коммерческого использования добавьте актуальный тариф конкретного договора, округление, различение входных/выходных токенов, сверку с отчетом поставщика и лимит на клинику. Не переносите демонстрационную оценку в финансовые документы. Цены и оговорки исследования приведены в [MARKET_RESEARCH.md](MARKET_RESEARCH.md).

Ошибки провайдера очищаются от сырого ответа и секретов. При отказе классификатора включается базовая логика; это помогает продолжить запись, но само по себе не является полной системой наблюдения за доступностью API. Мониторинг должен отдельно различать успешный внешний вызов и работу резервного режима без сохранения чувствительного содержимого.

Полный реестр прочитанных источников и ограничений: [SOURCES.md](SOURCES.md).
